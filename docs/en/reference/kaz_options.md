# kaz options

This page lists the options added or changed by the kaz fork (`tongsama/juicefs`) for `juicefs mount` and the other commands that share the client options. They are kept out of `_common_options.mdx` so that the upstream reference stays identical to upstream, which keeps later upstream merges free of conflicts in the docs.

Options added by kaz carry the `kaz-` prefix and their help text starts with `[kaz]`. Run `juicefs mount --help` for the complete list; this page explains the ones that need more than the help text.

|Items|Description|
|-|-|
|`--kaz-get-header-timeout=0`|[kaz] Max time to wait for the response headers of a block download; when it passes, the request is abandoned and the block is downloaded again through the usual retries (default: 0, disabled). It differs from `--get-timeout`: `--get-timeout` bounds the whole download (waiting for the response plus receiving the data), while this option bounds only the wait before the data starts, so a slow but flowing download is not cut. A block cut this way is fetched again without this limit for the next 5 minutes, so an object that always answers slowly is still read instead of failing every retry. Useful when the object store occasionally stalls before answering (for example, rclone serve s3 on Google Drive). Set it well above the normal download time.|
|`--max-deletes=10`|Background object deletion worker count (default: 10). Positive values use a bounded queue with `max-deletes × 10240` slice entries; a full queue waits for capacity. `0` disables slice object deletion. Negative values delete synchronously in the caller, **not** with unlimited concurrency, and can delay compaction and file writes; startup emits a warning.|
|`--kaz-finish-canceled-get`|[kaz] When a full-block download is canceled because its read is no longer needed (for example, dropped readahead), keep the download running and store the block in the disk cache instead of discarding it (default: false). Downloads that have not started yet are still skipped, and at most half of `--max-downloads` are kept running this way. Requires the disk cache.|
|`--kaz-writer-flush-timeout=0s`|[kaz] Local investigation branch: whole-file flush deadline. Default `0s` waits for pending commits without an elapsed-time deadline, including compaction and deletion-queue waits. Actual write errors still propagate. `auto` opts into the legacy retry-derived deadline (minimum 5 minutes); a positive duration opts into that deadline and may return EIO. Negative or invalid durations are rejected. The Linux FUSE server watchdog is also disabled in this branch so it cannot inject a separate 15-minute EINTR into pending operations. Kernel interrupt notifications still propagate, but server-forced interruption replies are removed. This applies to all FUSE requests, which can remain pending during a persistent backend stall. This does not change the existing writeback durability model or object-request retry limits. The old name `--writer-flush-timeout` still works as a deprecated alias.|
|`--kaz-writer-flush-scope=file`|[kaz] Local investigation branch: which pending writes `read` and `fallocate` commit before they run. Default `file` waits for every pending write of the file (prior behavior). `range` waits only for the pending writes of the chunks the request touches, plus earlier slices they depend on, and does not stop writes to other parts of the file; this shortens stalls on large, randomly written files such as VM images. A commit failure anywhere in the file that is already recorded, or occurs while waiting, is still returned; a later failure outside the range is returned by a later read, fsync or close. With `range`, a quota or space error of an out-of-range append can therefore surface after a fallocate that extends the file instead of from it, The wait happens before the file handle is locked, so reads and writes through the same handle are only held for writes that arrive during it. Applies to reads and fallocate through the mount (VFS); SDK and gateway reads through `pkg/fs` still wait for the whole file. `fsync`, `close`, `truncate` and `copy_file_range` always wait for the whole file. The old name `--writer-flush-scope` still works as a deprecated alias.|
|`--kaz-meta-write-batch=0`|[kaz] Local investigation branch: maximum number of consecutive pending slices of one chunk committed in a single metadata transaction. Default `0` commits one slice per transaction (prior behavior). Batching applies to every commit, including fsync and close, and keeps the creation order within a chunk. If a batch fails before writing anything (no such file, permission, no space or quota exceeded), its slices are retried one by one so each gets its exact error; a failure whose outcome is unknown (I/O or network error) is not retried and marks the file failed, as for a single slice. Implemented for Redis, SQL and TKV engines; TKV engines commit slices one by one when the change log is enabled, and SQL engines do so when a batch would take a chunk past the synchronous compaction threshold. The old name `--meta-write-batch` still works as a deprecated alias.|
|`--kaz-compaction-gc-mode=legacy`|[kaz] Local investigation branch: `legacy` retains obsolete-slice deletion-queue waiting. Opt-in `deferred` uses bounded hints after durable reference decrement to retire local staging before a nonblocking physical-delete enqueue. Remote queue saturation retains the durable marker and does not block later accepted local retirement. Local errors or active same-client staging PUTs keep deletion intent retryable. Requires positive max-deletes, writable metadata, and enabled background recovery. Hint overflow retains existing durable markers and their existing periodic recovery; it does not add a metadata format or higher-frequency scans. All writable clients must include the copy/clone snapshot guards before evaluating deferred mode. The old name `--compaction-gc-mode` still works as a deprecated alias.|
|`--kaz-compaction-scheduler=legacy`|[kaz] Local investigation branch: opt-in `priority` uses slice counts already available from Read/Write, 3 fixed buckets, 11 workers, one active job per inode and up to 1024 active/pending hints. No per-write metadata lookup or all-file/chunk scan. Hints are advisory; overflow can postpone cold work. Existing 2500-slice synchronous and manual compaction paths remain. The old name `--compaction-scheduler` still works as a deprecated alias.|
|`--kaz-writer-reuse-window=4`|[kaz] Local investigation branch: candidate age distance before an unmatched pending slice is frozen, integer 1..64. Default 4 retains prior behavior. Larger values can retain reusable partial slices longer, with more search/memory work. Gaps, completed-block rewrites, overlap ordering and explicit flush barriers are unchanged. The old name `--writer-reuse-window` still works as a deprecated alias.|
|`--kaz-writeback-fsync=true`|[kaz] When `--writeback` is enabled, `fdatasync` each staged block and `fsync` its directory before acknowledging the write, so staged data survives an OS crash or power loss. Set to `false` for higher write performance at the risk of losing staged blocks (left as empty files) on an OS crash. The old name `--writeback-fsync` still works as a deprecated alias.|
